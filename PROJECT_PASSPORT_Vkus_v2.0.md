
## 5. Правила записи файлов и хранения архивов

(1) Всё создание/редактирование/запись файлов проекта, включая паспорт/source/docs/archive, должно выполняться через авторизованный веб-интерфейс GitHub с использованием Fish. Не использовать GitHub API или локальную загрузку файлов в качестве замены.

(2) Fish должен быть виден. После сохранения/коммита необходимо заново открыть файл и проверить зафиксированное содержимое, точное наличие добавленного раздела и длину файла. Не сообщать о выполнении до прохождения проверки прочтения.

(3) Для каждого нового архива проекта создавать новую ветку в соответствующем репозитории, затем помещать новый архив туда.

(4) Перед сохранением нового архива удалять предыдущий архивный файл из репозитория, чтобы сохранялся только текущий архив, при этом исходный код и история Git-коммитов сохраняются.

(5) Проверять наличие архива, размер, целостность и возможность скачивания. Отчёт о статусе фактического тестирования и скриншот-доказательства предоставляются отдельно.

(6) Если какая-либо операция или проверка завершается неудачей, указать точную причину неудачи и не сообщать о выполнении.
