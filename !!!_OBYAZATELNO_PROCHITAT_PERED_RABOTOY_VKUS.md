Поиск не должен выдавать любое совпадение слова за клиента. Система должна отличать реальное намерение от: - случайного упоминания; - рекламы; - предложения услуги; - вакансии; - запроса на услугу/товар/помощь; - поиска исполнителя или сотрудника; - нерелевантного/устаревшего сообщения.

Актуальность и качество заявки важнее количества результатов.

Не считать тип намерения установленным только по ключевому слову. Учитывать контекст сообщения и, если доступно, дату/ответы/статус.

## 16. Vkus License Store — решение о переходе на Cloudflare Free (18.11.2026)

По прямому решению пользователя Lovable исключён из дальнейшей разработки и размещения магазина из-за платного ограничения. Не использовать редактор Lovable и Lovable hosting как целевую инфраструктуру. Текущий URL в `vkus/license_store.py` является временной/устаревшей зависимостью и должен быть заменён после переноса витрины.

Пользователь согласовал поэтапный запуск на бесплатной инфраструктуре Cloudflare (Workers Free + D1 + workers.dev) в качестве стартового проекта, с последующим переходом на платную инфраструктуру/сервер при росте клиентской базы и дохода. Упоминание 40 клиентов — ориентир пользователя для повторной оценки экономики, а не технический предел Cloudflare. 100 000 запросов в сутки — лимит Workers Free, а не количество заказчиков.

Проверенные официальные лимиты на 18.11.2026:
- Workers Free: 100 000 запросов/сутки, CPU 10 мс на запрос, память 128 МБ.
- D1 Free: 500 МБ на одну базу, 5 ГБ суммарно, 5 млн прочитанных строк/сутки, 100 тыс. записанных строк/сутки, до 10 баз, Time Travel 7 дней.
- При достижении дневных лимитов D1 запросы перестают выполняться до сброса лимита.
- workers.dev предназначен для личных/хобби-проектов, не являющихся business-critical; документация рекомендует production Workers на Workers Route или Custom Domain. Не утверждать, что любое получение платежа автоматически запрещено; перед реальными продажами перепроверить действующие условия и при необходимости получить подтверждение Cloudflare.
- Robokassa документирует iFrame для сайта и допускает WebView при технической совместимости. Это ещё нужно проверить на конкретном WebKitGTK/tkwry Vkus.

Обязательная целевая архитектура: Vkus Python/Tkinter/WebView → HTTPS Cloudflare Worker API + Static Assets → D1; Robokassa ResultURL/SuccessURL/FailURL; секреты Robokassa только в Worker Secrets; отдельный почтовый провайдер для доставки лицензии. API должен быть отделён от desktop-клиента, чтобы последующий перенос на платный сервер не требовал переписывания Vkus.

Требования безопасности:
- не хранить пароли Robokassa, секреты подписи, ключи API и административные секреты в исходниках Q322, клиентском Vkus, обычных vars, браузерном коде или логах;

- ResultURL подтверждает платёж только после серверной проверки подписи, суммы, номера заказа и статуса;
- SuccessURL/FailURL не являются подтверждением оплаты;
- callback идемпотентный, повторные уведомления не создают повторные лицензии;
- ключи генерируются криптографически стойко, клиент активирует их через серверную проверку;
- предусмотреть rate limiting, валидацию входных данных, CORS allowlist, защиту от повторов, резервный экспорт D1 и корректную обработку дневных лимитов;
